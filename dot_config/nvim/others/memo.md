# mini.ai カスタムテキストオブジェクト構築マニュアル

本マニュアルは、Neovimプラグイン `mini.ai` におけるテキストオブジェクトのカスタム定義において、Luaパターンエンジンのパースエラーおよび `mini.ai` の不透明なヒューリスティック処理（自動トリミング）によるバグを回避し、意図した通りの正確な挙動を保証するための客観的な設計指針である。

## 1. 基本原則：検索（Match）と抽出（Extract）の完全分離
句読点や記号（例：指数表記の `e`、パスの `/` など）を含む複雑な文字列をテキストオブジェクトとして定義する場合、単一のLuaパターン内で「対象の検索」と「領域の指定（キャプチャ）」を混在させてはならない。
客観的に最も安全かつ決定論的なアプローチは、公式ドキュメントに定義されている「連続評価（Consecutive Evaluation）」構文を用いた2段階処理の採用である。

## 2. アンチパターン（発生する不具合と論理的理由）

* **[NG] 境界指定 `%f` と位置キャプチャ `()` の混在**
    * **事象:** `No textobject found` エラーの発生。
    * **根拠:** Luaの `string.find` エンジンにおいて、幅を持たないゼロ幅アサーション（Frontier pattern `%f` など）と、同じく幅を持たずバイトインデックスを返す位置キャプチャ `()` を同一パターン内で隣接・混在させた場合、内部のインデックス算出が破綻しマッチ自体が棄却される。
* **[NG] 両端キャプチャ `()...()` による単一文字列での抽出**
    * **事象:** 意図しない領域の分割（例：`6.022e23` に対し `23` のみが抽出対象となる）。
    * **根拠:** `mini.ai` の仕様上、`a` (around) と `i` (inside) の領域境界が同一であると判定された場合、内部の記号（非単語構成文字）をエッジとして誤認し、領域を自動的に縮小するヒューリスティック機能が発動するためである。

## 3. 解決策：ベストプラクティス（標準設計テンプレート）

`mini.ai` の連続評価（配列構文）を利用し、以下の構造で記述することを標準の設計方針とする。これにより、Luaエンジンのエラーを回避し、かつ `mini.ai` の自動裁量を完全に無効化する。

```lua
custom_textobjects = {
    -- 構文: target_name = { { 検索パターンの配列 }, '抽出パターン' }
    target_name = {
        {
            -- Step 1: 検索フェーズ
            -- 役割: 対象文字列を正確に特定する。
            -- 規則: キャプチャ () を一切使用せず、純粋なパターンマッチ（%f等を含む）のみを記述する。
            '%f[%w]pattern_example_1%f[^%w]',
            '%f[%w]pattern_example_2%f[^%w]',
        },
        -- Step 2: 抽出フェーズ
        -- 役割: mini.ai の自動トリミングを封じ、対象領域を強制定義する。
        -- 規則: 常に '^().*()$' を適用する。これにより「マッチした文字列の先頭から末尾まで」が
        --       例外なく a および i の対象領域として絶対指定される。
        '^().*()$',
    }
}
```

## 4. 実装例（数値オブジェクト `n` の完全定義）

上記テンプレートに則った、エラーおよびバグを完全に排除した数値抽出の実装例である。

```lua
n = {
    {
        -- 1. 指数表記
        '%f[%d%.%-%+][%-%+]?%d+%.?%d*[eE][%-%+]?%d+%f[^%d%.eE]',
        '%f[%d%.%-%+][%-%+]?%.%d+[eE][%-%+]?%d+%f[^%d%.eE]',
        -- 2. 浮動小数点・整数
        '%f[%deE%.%-%+][%-%+]?%d+%.?%d*%f[^%d%.eE]',
        '%f[%deE%.%-%+][%-%+]?%.%d+%f[^%d%.eE]',
    },
    '^().*()$',
}
```

## 5. 出典および論理的根拠
* **連続評価構文の仕様:** Neovimプラグイン `mini.ai` ローカルヘルプドキュメント `:h mini.ai-custom-textobjects` 内 `Consecutive evaluation` の項に基づく。
* **パターンマッチングエンジンの制約:** Lua 5.1 Reference Manual `5.4.1 - Patterns` におけるゼロ幅アサーションおよびキャプチャの技術的仕様に基づく。
